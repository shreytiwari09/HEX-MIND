# Live agent progress UI in coding agents and app builders (as of Nov 2026)

Scope: Devin, Cursor, Claude Code (desktop and agent view), GitHub Copilot coding agent, OpenHands Agent Canvas, Replit Agent 4, Lovable, Bolt, Kiro, Cline Kanban. Purpose: patterns for redesigning the H.E.X Mind mission screen. Where a finding comes from a search-result snippet or a third-party source rather than a page read directly, the note says so.

## 1. How they show "who is working on what right now"

### Takeaway
The dominant 2026 pattern is a **list or board of agent rows/cards, grouped by state**. Each row has an animated state icon, a one-line plain-language "currently doing" summary, and an age or elapsed time. Child agents roll up into their parent, which shows a short live status line and expands on demand. Nobody in this set showed a separate "heartbeat" widget; liveness comes from the animated icon plus a summary line that updates often.

### Cited Findings
- **Claude Code agent view** (`claude agents`, 2026): sessions are grouped as Pinned / Ready for review / Needs input / Working / Completed, with a header line counting awaiting-input, working and completed sessions. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- Each Claude Code row has a state icon (colour and animation encode state), a name, a **one-line summary of current activity generated by a Haiku-class model** ("a working row shows what the session says it's doing, a blocked row shows the question it's asking"), an age, and a PR label coloured by status. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- Working rows' summaries **update at most every 15 seconds** and are rewritten at the end of each turn. A finished session's age **freezes at the run's duration**. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- Claude Code states: Working (animated), Needs input (yellow), Idle (dimmed), Completed (green), Failed (red), Stopped (grey). A `/loop` session shows a run count and a countdown ("in 4m"). — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- Claude Code subagents **do not get their own rows**. They roll up into the parent's state ("a running subagent counts as working"), and `Tab` browses all subagents. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- Claude Code also surfaces attention outside the list: the terminal tab title shows "2 awaiting input", and notifications fire when a session needs input, finishes or fails. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- **Claude Code desktop redesign** (14 Apr 2026): a sidebar holds every active and recent session and can be filtered by status, project or environment. Sessions auto-archive when their PR merges or closes, so the sidebar shows only live work. — [claude.com blog](https://claude.com/blog/claude-code-desktop-redesign)
- **GitHub Copilot coding agent** (19 Mar 2026): when Copilot delegates to a subagent, that activity is **collapsed by default, with a "heads-up display" showing what it is currently doing**, expandable to full output. — [GitHub changelog](https://github.blog/changelog/2026-03-19-more-visibility-into-copilot-coding-agent-sessions/)
- **Cline Kanban** (research preview): each card "displays the agent's **latest message or tool call** so you can monitor progress from the board". Each card is one task with its own git worktree and terminal. — [docs.cline.bot core workflow](https://docs.cline.bot/kanban/core-workflow.md); [docs.cline.bot features](https://docs.cline.bot/kanban/features)
- **Replit Agent 4** (2026): parallel tasks appear on a board with columns Drafts / Active / Ready / Done, moving left to right. In thread view, "each task runs in its own thread with a **live status indicator**". — [docs.replit.com task system](https://docs.replit.com/core-concepts/agent/task-system)
- **Devin**: the coordinator session spins up "managed Devins", each in its own VM, and monitors them, including their ACU usage. Child sessions appear **indented under the parent in the sidebar** (2025 release note; from a search snippet, not read directly). — [Cognition blog](https://cognition.ai/blog/devin-can-now-manage-devins); [docs.devin.ai advanced capabilities](https://docs.devin.ai/work-with-devin/advanced-capabilities); [Devin 2025 release notes](https://docs.devin.ai/release-notes/2025)
- **Cursor 3 Agents Window** (Apr 2026): a sidebar lists foreground and background agents with pinning, and agents run "locally, in worktrees, in the cloud, and on remote SSH". A tiled layout (13 Apr 2026) splits the view into panes "to run and manage several agents in parallel". — [cursor.com changelog 3.0](https://cursor.com/changelog/3-0); [cursor.com changelog page 10](https://cursor.com/changelog/page/10)
- **Lovable** Build mode: the task card in chat shows "the current step, the files being changed, the tools in use (search, web fetch, image generation), and how far a multi-step implementation has progressed". — [docs.lovable.dev agent mode](https://docs.lovable.dev/features/agent-mode)

### Inferences
- For H.E.X Mind, a **persona roster strip** (PM, Backend, Frontend…) would let a user see at a glance who is working. Each persona would get a state icon (working animated / waiting / idle / done / failed), a one-line "now doing" sentence (for example, "Backend · writing `api/routes.py` · feature F3"), and an elapsed timer. This roster is the direct fix for "nothing shows which agent is working right now".
- The "now doing" line can be built deterministically from real events (the latest tool call name and target file, or "waiting for model reply · 42 s"). That keeps it within the never-fabricate rule. Claude Code's model-written summary is an option only if the line is marked as a summary.
- Claude Code freezes a finished run's age at its duration. For H.E.X Mind this means elapsed timers on finished features should show their real duration rather than keep counting.

### Gaps
- No official source describes the visual layout of Cursor's agent rows (status badges or timers), Devin's sidebar status icons, or Cline's card status values.
- No product documents an explicit "heartbeat" or "last event N seconds ago" indicator. Claude Code's 15-second summary refresh comes closest.

## 2. How they show progress during long waits

### Takeaway
They layer three signals. (a) A **plan or todo checklist** that ticks over (Cursor todos, Kiro tasks.md status, Replit columns). (b) A **stream of steps and tool calls** with a "current step" highlighted (Lovable visible tasks, Devin Progress tab, Copilot logs). (c) **Attention cues**: state colours, notifications, "waiting 3m" counters. None of the official docs found promise an ETA. Instead they show elapsed time, step counts and running cost.

### Cited Findings
- **Cursor** introduced structured to-do lists in 1.2 (2025, older) "making long-horizon tasks easier to understand and track". In Aug 2025 (older), background agents gained status updates "through a comment and todos". — [cursor.com changelog 1.2](https://cursor.com/changelog/1-2); [cursor.com changelog 1.4](https://cursor.com/changelog/1-4)
- Cursor 3 (2 Apr 2026) fixed todo cards that disappeared after all todos completed. Users want the finished checklist to stay visible. — [cursor.com changelog 3.0](https://cursor.com/changelog/3-0)
- Cursor 2.0 (late 2025, older; from a search snippet) added "a sidebar for your agents and plans", including "plan with parallel agents". A later release lets you minimize the plan shown above the prompt, and the chat renders the to-do list when the agent reads it (also from a search snippet). — [cursor.com changelog 2.0](https://cursor.com/en-US/changelog/2-0); [cursor.com changelog](https://www.cursor.com/changelog)
- **Kiro** specs: the task execution interface "displays real-time status updates; tasks are updated as in-progress or completed". "Run all" builds a dependency graph from tasks.md into **waves**: "Waves execute sequentially; tasks within a wave execute concurrently." — [kiro.dev specs](https://kiro.dev/docs/specs/)
- In Kiro, a "Start task" link above each task switches it to "Task in progress" (from a guide and a community workshop, not the core docs). — [kiro.dev learn-by-playing](https://kiro.dev/docs/guides/learn-by-playing/05-using-specs-for-complex-work/); [AWS UG workshop](https://awsugbne.github.io/kiro-workshop-feb26/executing/running-tasks)
- **Replit**: before running, each proposed task has a title, a description and a plan with "what done looks like" (View plan → Accept tasks / Revise plan). Progress is then shown by which column the task sits in. — [docs.replit.com task system](https://docs.replit.com/core-concepts/agent/task-system)
- Replit checkpoints are snapshots made automatically "at feature completion and major milestones", each with a git commit (from a search snippet). — [docs.replit.com checkpoints](https://docs.replit.com/core-concepts/agent/checkpoints-and-rollbacks)
- **Lovable**: the "More options" menu under a response shows **Credits used while the request runs**, then the final cost. Build runs can last up to 10 hours, and in the last half hour Lovable "wraps up and summarizes what remains". The docs describe no on-screen timer. — [docs.lovable.dev agent mode](https://docs.lovable.dev/features/agent-mode)
- Lovable lets users send follow-ups mid-build, which it "picks up at its next natural stopping point". **Bolt** has prompt queueing, so you can type the next prompt while it builds and it runs when the current build finishes. — [docs.lovable.dev agent mode](https://docs.lovable.dev/features/agent-mode); [bolt.new blog](https://bolt.new/blog/prompt-queueing)
- **Copilot** session logs show "internal monologue and the tools it used". Since Mar 2026 they also show environment setup steps, such as cloning and firewall start, so the pre-work phase no longer looks idle. `gh agent-task view --log --follow` streams live. — [docs.github.com logs](https://docs.github.com/en/copilot/using-github-copilot/coding-agent/using-the-copilot-coding-agent-logs); [GitHub changelog](https://github.blog/changelog/2026-03-19-more-visibility-into-copilot-coding-agent-sessions/)
- **Claude Code**: a waiting session shows "waiting 3m" in peek, and the desktop app has Verbose / Normal / Summary view modes that control how much tool-call detail is shown. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view); [claude.com blog](https://claude.com/blog/claude-code-desktop-redesign)
- **Devin**: commands not yet run appear greyed out in Command History ("run at a future point"), and Devin can do several actions at once (browser plus shell plus file reads). — [docs.devin.ai session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)

### Inferences
- For H.E.X Mind's long model calls, the main staleness risk is the gap between events. The pattern that addresses it is (a) an elapsed counter on the current step, for example "Calling gpt-x · 38 s", which can be driven by the real request start. That timer is factual, unlike an invented ETA. It should be paired with (b) the milestone/feature checklist ticking over, and (c) showing setup phases (sandbox start, worktree create) as steps, like Copilot does.
- The finished checklist should stay visible after completion (Cursor's bug fix shows users care).
- Live running cost per persona and per feature, as Lovable does, fits the observability data H.E.X Mind already collects.

### Gaps
- None of the official docs found promise an ETA or percent-complete. If any product shows one, I found no source for it.
- No primary source documents Bolt's in-build progress UI. Only open-source bolt.diy code was found, which may not match the current product.

## 3. How they let users drill into one agent or step without leaving the main screen

### Takeaway
Drill-down is **in place**: a peek panel or side panel, an expandable step or tool call, or a details pane that temporarily replaces the preview. The detail view is usually tabbed: Timeline/Log, Changes/Diff, Terminal/Shell, Browser/Preview. Steps link to their evidence (commands, diffs), and clicking an item jumps to that moment.

### Cited Findings
- **Claude Code peek**: pressing Space on a row opens a panel without attaching. It shows the exact question with numbered choices when the session is waiting, the result when finished, or the full status sentence when working. You can reply inline or send `/stop`. Pressing Enter or → attaches to the full session, and Claude **posts a short recap of what happened while you were away**. — [code.claude.com agent view](https://code.claude.com/docs/en/agent-view)
- **Lovable**: clicking the activity card opens a Details panel **where the preview normally is**, with a **Timeline** tab (every step including tool calls), a **Changes** tab (file changes), and "Hide details" to return. — [docs.lovable.dev agent mode](https://docs.lovable.dev/features/agent-mode)
- **Devin**: the Progress tab is one unified worklog ("all shell commands, code edits, and browser activity will be logged in one unified view"). Clicking a step opens its details, shell commands are linked to progress updates, and clicking a command jumps to that point in the session. Other tabs: an IDE (watch edits in real time), a Browser/Computer tab (interactive), and Preview. Side chats open "in a panel next to the worklog" and are read-only. — [docs.devin.ai session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)
- **Copilot**: subagent output is collapsed with a live HUD and expands in place. On github.com, logs sit next to the Overview and Files changed tabs. — [GitHub changelog](https://github.blog/changelog/2026-03-19-more-visibility-into-copilot-coding-agent-sessions/); [docs.github.com track sessions](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/track-copilot-sessions)
- **Cline Kanban** card detail: agent terminal (conversation plus actions), diff against the base branch with **checkpoints that scope the diff to specific message ranges**, and inline comments on diff lines to steer the agent. — [docs.cline.bot core workflow](https://docs.cline.bot/kanban/core-workflow.md)
- **Replit**: a finished task's review screen shows "the work log, test results, and a live preview of the changes", with apply or dismiss. — [docs.replit.com task system](https://docs.replit.com/core-concepts/agent/task-system)
- **Claude Code desktop**: drag-and-drop panes (terminal, file editor, diff viewer, preview) in a grid, and side chats (⌘;) that branch without polluting the main thread. A community feature request says the desktop Tasks pane lists running subagents and background shell commands but not the todo checklist, and does not stream each subagent's activity live. That is a reported gap, not official. — [claude.com blog](https://claude.com/blog/claude-code-desktop-redesign); [claudeissues.com #57019](https://claudeissues.com/issue/57019-feature-request-show-todowrite-task-list-in-claude-app-tasks-panel); [claudeissues.com #75863](https://claudeissues.com/issue/75863-feature-vscode-extension-add-a-background-tasks-panel-parity-with-desktop-app)
- **OpenHands Agent Canvas**: the browser UI covers conversations, files, terminals and automations, and conversations can be branched. A third-party source tour says events stream over WebSocket into a store that dedups by id and merges streaming deltas. A design doc says each observation is **paired with its originating action** so a card shows both. Both are non-official. — [docs.openhands.dev overview](https://docs.openhands.dev/openhands/usage/agent-canvas/overview); [pyshine source tour](https://pyshine.com/OpenHands-Agent-Canvas-Source-Tour/); [enyst design doc](https://enyst.github.io/arch/agent-canvas-tool-visualizers.html)

### Inferences
- For H.E.X Mind, clicking a persona in the roster could open a **right-side drawer** on the mission page. The drawer would have tabs: Live (streamed model output and tool calls for that persona's current feature), Steps (an expandable list pairing each tool call with its result), Changes (git diff for the feature, scoped by step like Cline's checkpoints), and Checks (run_check sandbox results). This replaces jumping to the Observability page for the common case.
- Pairing each action with its observation, as OpenHands does (write_file → path and size; run_check → exit code and output), fits H.E.X Mind's "agent claims aren't evidence" rule. The drawer would show the git and sandbox evidence next to the claim.
- A short "while you were away" recap when the user returns to a mission, as Claude Code does on attach, could be built from real events.

### Gaps
- Exact layouts of the Cursor Agents Window detail pane and the OpenHands official event-card UI were not found in official docs.

## 4. How they combine plan, live activity, logs and cost in one view vs. separate pages

### Takeaway
The 2026 consensus is **one workspace with switchable or tiled panes**, not separate pages. There is an overview (list or board of agents and tasks), plus a per-agent detail made of tabs or panes (timeline, diff, terminal, preview, plan). Raw logs sit one click deep, and cost is a small inline figure. Deep telemetry, where it exists, is a secondary surface.

### Cited Findings
- Claude Code desktop: chat plus rearrangeable panes (terminal, editor, diff, preview) and a usage button for context and session usage, all in one window. — [claude.com blog](https://claude.com/blog/claude-code-desktop-redesign)
- Devin: Progress/worklog, Shell, IDE, Browser and Preview are tabs of the one session view, and steps link across them. — [docs.devin.ai session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)
- Cursor 3: the Agents Window coexists with the IDE ("have both open simultaneously"). Plans open as tabs with document behaviours and are included in shared chats with the transcript. — [cursor.com changelog 3.0](https://cursor.com/changelog/3-0); [cursor.com changelog page 10](https://cursor.com/changelog/page/10)
- Replit: two views of the same tasks (board for overview, thread for following one), plus a review screen per task. — [docs.replit.com task system](https://docs.replit.com/core-concepts/agent/task-system)
- Lovable: chat with task cards, plus a Details panel swapped into the preview slot (Timeline / Changes), plus credits shown per response. — [docs.lovable.dev agent mode](https://docs.lovable.dev/features/agent-mode)
- Copilot: logs sit beside Overview and Files changed on the agents page, with raw Actions logs kept elsewhere and setup output now pulled into the session log so users needn't open them. — [GitHub changelog](https://github.blog/changelog/2026-03-19-more-visibility-into-copilot-coding-agent-sessions/); [docs.github.com manage agents](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)

### Inferences
- A possible H.E.X Mind mission screen in three zones:
  1. **Top: persona roster** with live state, the "now doing" line and an elapsed timer.
  2. **Left/centre: plan** (milestones → features as a checklist or board with columns Planned / Building / Validating / Done, each card showing its persona avatar and the latest tool call).
  3. **Right drawer: drill-down** into the selected persona or feature (Live / Steps / Changes / Checks / Cost tabs).

  Mission cost and tokens would sit in a slim header. The existing Observability tabs (Trace, Blackboard, A2A, Topology…) would stay, but would be reachable as an "Advanced" tab inside the drawer or deep-linked from a step, filtered to that step. That closes the "two pages are far apart" complaint.
- The raw "live output" log becomes the per-persona Live tab rather than one interleaved stream.

### Gaps
- No source quantifies the effect of these patterns (for example, reduced abandonment). The claims are product design choices, not measured outcomes.
