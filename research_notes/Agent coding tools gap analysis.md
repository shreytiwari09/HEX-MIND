# H.E.X Mind wins on trust, loses at shipping

H.E.X Mind is ahead of every tool surveyed on control and verifiability, and behind almost all of them on the last mile from idea to live URL. No competitor combines a fixed team of role personas, per-persona models from any provider with a measured Auto assigner, QA-written acceptance tests run in a local Docker sandbox, apply-only-on-approval git worktrees, and per-call token, cost and latency traces. The app builders (Lovable, Bolt, Replit, v0), and since 5 November 2026 Cursor, now make "shipped" a one-click act: they host the app, bundle a database and sign-in, show a live preview you can click to edit, and accept a screenshot or Figma frame as input. H.E.X stops at a localhost link. For a non-technical user who wants to ship, the ten gaps that matter most are therefore about publishing, seeing and steering the app, not about agent architecture, where H.E.X is already at or above parity. The field has also thinned: AutoGen is archived, Roo Code shut down, GPT-Pilot is unmaintained and shipped a credential stealer, and MetaGPT has gone commercial as Atoms. That leaves the open, local-first, verifiable "AI software team" position largely empty, which makes closing the shipping gap worth more than adding agent features.

## Four product families now split the market, and none matches H.E.X's shape

The tools fall into four groups with different centres of gravity. **App builders** (Lovable, Bolt.new, Replit Agent, v0) are browser-based, chat-first and aimed at non-coders; each has a live preview beside the chat, point-and-click visual editing, Figma import, image or URL input and version restore ([Lovable preview toolbar](https://docs.lovable.dev/features/preview-toolbar.md); [Bolt visual edits](https://support.bolt.new/building/visual-edits.md); [Replit visual editor](https://docs.replit.com/design/visual-editor.md); [v0 Design Mode](https://v0.app/docs/design-mode)). **Autonomous SWE agents** (OpenHands, Devin, Copilot cloud agent, Cursor cloud agents) work on an existing repo in a cloud VM and hand back a PR; in 2026 all added sub-agents, MCP, skills and Slack-style triggers, and Devin and Cursor give the agent a full desktop and browser that records **screenshots and video as proof of work** ([Cursor cloud agent docs](https://cursor.com/docs/cloud-agent); [Devin docs](https://docs.devin.ai/)). **IDE and CLI agents** (Claude Code, Cline, Aider, Kiro) have converged on plan modes, reviewable diffs, checkpoints, hooks, instruction files and subagents ([Claude Code checkpointing](https://code.claude.com/docs/en/checkpointing.md); [Cline checkpoints](https://docs.cline.bot/core-workflows/checkpoints.md); [Kiro specs](https://kiro.dev/docs/specs/)). **Role-based multi-agent frameworks** (MetaGPT/Atoms, ChatDev, GPT-Pilot, AutoGen/Magentic-One/Microsoft Agent Framework, CrewAI) are the closest in spirit to H.E.X but have mostly stopped being software-building products.

That last group's state matters for positioning. **AutoGen is archived** and points users to Microsoft Agent Framework, which reached 1.0 on 3 April 2026 with checkpointing, human approvals and a Magentic orchestration pattern but no documented code sandbox ([MAF 1.0 blog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). **ChatDev 2.0 (January 2026) became a general zero-code agent platform**, moving the old "software company" to a legacy branch ([ChatDev README](https://raw.githubusercontent.com/OpenBMB/ChatDev/HEAD/README.md)). **GPT-Pilot is unmaintained and carried credential-stealing code in `core/telemetry/` from August 2025 to 11 June 2026** ([GitHub gpt-pilot](https://github.com/Pythagora-io/gpt-pilot)), a concrete case for H.E.X's rule that third-party code is untrusted. **Roo Code shut down on 15 May 2026** ([Roo Code docs](https://roocodeinc.github.io/Roo-Code/)). MetaGPT became **Atoms on 13 January 2026**, a commercial product with eight named agents and a "Race Mode" that runs best-of-N attempts across models ([KrASIA](https://kr-asia.com/from-metagpt-to-atoms-deepwisdom-leads-chinas-push-into-vibe-coding); [Atoms blog](https://atoms.dev/blog/introduce-race-mode)). CrewAI itself is very active (1.15.44 on 19 November 2026, against H.E.X's pinned 1.15.28) but ships **no official software-development crew** and has **deprecated its built-in code execution** in favour of external sandboxes, which H.E.X already does ([CrewAI Agents docs](https://docs.crewai.com/en/concepts/agents)).

Two cautions temper the "ahead" rows. Sandboxed verification alone no longer differentiates: **v0 states that "every action runs in an isolated sandbox"** and opens and tests the apps it builds ([v0 agentic features](https://v0.app/docs/agentic-features)), and Lovable's build mode verifies with browser and frontend tests ([Lovable agent mode](https://docs.lovable.dev/features/agent-mode.md)). And H.E.X's skills and MCP plugins are at parity on mechanism, not ahead: Copilot, Devin, Cursor, Claude Code, Kiro and Cline all ship skills, custom agents and MCP ([GitHub Blog](https://github.blog/ai-and-ml/github-copilot/whats-new-with-github-copilot-coding-agent/); [Kiro docs](https://kiro.dev/docs/)). What remains genuinely distinctive is the combination: per-persona heterogeneous models chosen from measured account data, acceptance-test gates, apply-on-approval, and dollar-level traces. Competitors bill in opaque credits; **Lovable gives "no upfront estimate"** of a request's cost ([Lovable agent mode](https://docs.lovable.dev/features/agent-mode.md)), and Bolt "selects the model behind the scenes" ([Bolt agents](https://support.bolt.new/building/agents.md)). No surveyed product publishes a fixed persona team with per-role models, and none documents QA-written acceptance tests as the gate before work is accepted.

## Ten gaps, ranked by what a non-technical user feels first

The ranking weighs how directly each gap blocks a non-coder from getting a working, shareable app. Every approach keeps H.E.X's constraints: CrewAI and Google ADK only, no LiteLLM, all model calls through ProviderRouter, untrusted code in the sandbox, and no keys or tokens in the sandbox, renderer or logs.

| # | Gap | Who sets the bar | Suggested approach within H.E.X's constraints |
|---|---|---|---|
| 1 | **Publish to a live URL** | Lovable, Bolt, Replit, v0, Cursor Apps | Build in the sandbox, then have the backend (not the sandbox) push the artifact through a host's deploy API with the user's token from the OS keychain, behind an explicit Publish approval, as P9. |
| 2 | **Live preview pane** | All app builders, Claude Code Desktop | Embed an Electron webview on the sandbox's localhost port (lifting D41/D45's deferral), reusing the existing run-app link. |
| 3 | **Backend services without accounts** | Lovable Cloud, Bolt Cloud, Replit | Ship a local Postgres or SQLite plus a vetted auth library in the sandbox project layout; offer Supabase as an MCP plugin for publish, with its keys held by the backend. |
| 4 | **Browser tests with screenshot proof** | Devin, Cursor, v0, Claude Code | Give the QA persona a Playwright tool inside the Docker image, store screenshots as run artifacts from the sandbox (not agent claims), and show them in mission chat (needs dependency approval). |
| 5 | **Image, screenshot and Figma input** | All app builders | Accept attachments in chat, route them through ProviderRouter, and let Auto prefer vision-capable models for designer and frontend personas; add Figma as an MCP plugin. |
| 6 | **One-click undo** | Claude Code rewind, Cline shadow git, Lovable history | Commit the worktree after each accepted feature and expose "restore to this milestone" in chat, since the git machinery already exists. |
| 7 | **Click-to-edit on the preview** | v0 Design Mode, Lovable, Bolt | Let the user click an element in the preview pane and send its selector and screenshot to the frontend persona as a scoped Edit request via the existing Ask/Edit/Auto router. |
| 8 | **Reviewable plan before building** | Kiro specs, Lovable and Replit plan modes | Render the PM's milestones, features and acceptance criteria as an editable spec with comments, and pause the ADK workflow until the user approves it. |
| 9 | **Starter templates** | Lovable, Bolt, v0 | Ship vetted per-project-type skeletons (web app, CRUD with auth, CLI, Streamlit) as signed first-party skills the PM picks from, which also lifts acceptance-test pass rates. |
| 10 | **Recovering stuck missions** | Magentic-One progress ledger and stall counter | Add a progress check in the ADK loop that flags looping or stalling and asks the user to replan or resume from the last checkpoint, keeping D53's no-automatic-resume decision. |

Just outside the ten sit payments (all four builders offer Stripe paths), GitHub sync, OS notifications, and native mobile, which only Replit offers through Expo and TestFlight ([Replit mobile](https://docs.replit.com/build/mobile-first-app.md)). Gaps 1, 2 and 4 together are what competitors would call the core loop; Cursor's November launch shows the pattern converging: build, preview, run security checks, and **"nothing goes live until the checks pass and you explicitly publish"** ([Cursor changelog](https://cursor.com/changelog)). That sentence is almost H.E.X's apply-on-approval rule restated for deployment, so P9 can extend an existing principle rather than invent one.

Every hosted path charges for it: the app builders sit at **$20 to $30 a month** entry plans, with custom domains gated behind payment ([v0 pricing](https://v0.app/pricing); [Bolt pricing](https://bolt.new/pricing); [Replit pricing](https://replit.com/pricing)). A local-first H.E.X has a different option the cloud tools cannot offer: deploy to the user's own account at a host they choose, with no platform markup, matching its bring-your-own-key model stance.

## Conclusion

The research shifts where H.E.X's next effort pays off. Agent architecture is no longer the frontier: subagents, skills, MCP and model pickers became table stakes across the field in 2026, and the role-persona frameworks that pioneered H.E.X's model either pivoted or died. The frontier is the last mile, where Cursor's "check, then explicitly publish" design shows the market moving toward H.E.X's own approval philosophy. H.E.X's evidence-first design (acceptance tests from the sandbox, changes from git, costs from traces) is the right foundation for a publish gate that blocks release until QA and security pass, something only Replit and Cursor approximate. The gamble is the inverse: without a preview, screenshot proof and a publish button, a non-technical user never sees that rigor.

Some uncertainty remains. No independent 2026 head-to-head benchmark of app quality or success rate across these tools was found, so the claim that H.E.X's gates produce better apps is untested until P8's experiments run with real keys. Pricing for Cursor Apps and OpenHands Cloud is unpublished or from third parties, and the models behind Lovable, Bolt and Replit are not named in first-party docs. Two of the suggested approaches (Playwright in the sandbox, a deploy-host integration) need dependency approval, and stall recovery must respect the recorded decision against automatic resume (D53).
