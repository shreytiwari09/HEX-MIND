# UI and UX

- Start from the user's task: what do they do here, and what is the one primary action?
- Hierarchy: one clear heading, group related things, give the primary action the strongest
  visual weight, and keep secondary actions quiet.
- Consistency: reuse the project's spacing scale, type scale and components before inventing new ones.
- States: every screen has loading, empty, error and success states. Empty states say what to do next.
- Forms: visible labels (not placeholders), inline errors next to the field, the submit button
  says what it does, and the keyboard order follows the visual order.
- Copy: plain words, sentence case, no jargon; error messages say what happened and how to fix it.
- Responsive by default: content readable from phone width up; no horizontal page scroll.
